## Tools

tablex-mcp 0.1.4 and MongoDB Shell 0.1.1. Update them in **Driver Manager → Tools** (the MongoDB Shell sits under the MongoDB driver), then restart your MCP client.

## What's new

- **tablex-mcp: MongoDB queries.** `mongo_find`, `mongo_aggregate` and `mongo_count` read MongoDB collections with **Read** access or more: filters, projections, sorts and pipelines in Extended JSON, at most 1000 documents (200 by default), with `truncated` set when the result was cut. They are read-only: the MongoDB driver refuses anything that writes, `$out` and `$merge` included. A MongoDB connection no longer counts as browse-only.
- **tablex-mcp: MongoDB changes.** `mongo_insert`, `mongo_update` and `mongo_delete` with **Read and write** access and **Let MCP clients run changes** on, never on a production connection type. Each one shows you the database, collection and command and runs only when you accept. An update or delete with an empty filter is refused unless asked for explicitly, and then it counts as dangerous.
- **tablex-mcp: `execute_batch`.** A script of several SQL statements in one call, with a result per statement: it stops at the first error unless `continue_on_error` is set, and `use_transaction` runs it as one transaction that is rolled back on any error. You approve the whole script once; it is refused before anything runs if one statement is not allowed.
- **tablex-mcp: show it in TableX.** With TableX 0.1.8 open, `open_table` opens a table or collection and `execute_and_show` puts a query in a new tab, running it there when it is a single read (anything else waits for you to press Run). Both need the connection's agent access.
- **tablex-mcp: connections.** `add_connection`, `duplicate_connection` and `remove_connection`, each one asked first (the question never shows a password), with **Let MCP clients run changes** on. A password given with a new connection goes to TableX's credential store. A new or copied connection follows your agent access settings; a copy never gets more access than the original. An open TableX picks up the change at once.
- **MongoDB Shell: statement by statement.** A script runs one statement after the other, as a MongoDB shell does: a statement that does not parse fails at its own line instead of stopping the whole script before it starts, and with **On script error → Run the remaining statements** (TableX 0.1.8) the statements after a failed one still run, with its error in the Output.
