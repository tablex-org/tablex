## What's new

- **SQL Server and DuckDB.** Two new drivers in **Driver Manager**.
  - **SQL Server:** sign in with a user name and password, browse databases, schemas, tables and views, run queries and edit rows.
  - **DuckDB:** open a `.duckdb` file (or **Open read-only**), or use **In memory** for a scratch database.
- **Open data files as tables.** **File → Open Data File…** (also in the command palette, or drop the files on the sidebar or an editor) opens CSV, TSV, JSON, NDJSON and Parquet files.
  - Each file becomes a view in a **Files** connection, with sorting, filtering, paging and export like any table. An editor tab on it can join several files with SQL.
  - Files are read in place, page by page, never loaded whole. Reopening a file shows what it holds now.
  - It uses the DuckDB driver; tablex offers to install it the first time.
- **Query History.** A tab with every run on every connection: when, how long, how many rows or the error, and the statement.
  - Search, and filter by connection, database, date, kind (queries, data changes, schema changes, Redis commands) and result. MCP calls are listed too.
  - **Open in new tab**, **Insert into editor**, **Copy SQL**, **Run** (it asks first when the statement can change something), **Delete** and **Clear**.
  - Clicking an entry in a tab's own history strip now puts it in the editor instead of running it.
  - **Settings → Query & Connections**: **Record query history** and **Keep query history for (days)**.
- **See what an UPDATE or DELETE will change.** When tablex asks before an UPDATE or DELETE, it also counts the rows it will change and shows the first few, read-only. **Settings → Editor → Preview affected rows before UPDATE/DELETE** turns it off.
- **Agent access in one place.** **Settings → AI Assistant → Default agent access** now goes up to **Read and write** for connections that are not Production; each change an agent asks for still needs your approval, and Production connections still need a level of their own. The separate "Let MCP clients run changes" switch is gone. If some of your connections are already set to Read and write, tablex lists them once after the update.
- **Approve MCP changes in tablex.** When an MCP client cannot ask you itself, tablex shows the request (connection, statement, what is dangerous about it) and runs nothing unless you click **Approve**.
- **WHERE and ORDER BY completion.** The filter and sort boxes of a table tab suggest its columns, keywords and functions.
- **A faster sidebar.** The tree redraws only when what it shows changes, and the columns of a whole schema are read in one request, so opening **Columns** folders and completing `FROM a JOIN b` no longer ask the server once per table.
- **Cell details in a window.** The **Value** panel can open **In a window of its own**.
- **Settings in the toolbar.** The **Settings** button moved from the title bar to the toolbar, next to **Assistant**.
- **Windows on Arm.** A native build for Windows 11 on Arm (`aarch64`), next to x86_64.

## Fixes

- **Driver Manager** labelled drivers installed from the catalog as "Developer driver", and that label hid **Update**. Only drivers you installed in Developer mode carry it now.

## Before you update

- Update the drivers and `tablex-mcp` in **Driver Manager**. PostgreSQL 0.1.5 is needed to preview an UPDATE or DELETE inside an open transaction.
- Every driver is now licensed under the AGPL-3.0, like tablex.
