## What's new

- An **Updates** button in the title bar opens the Update Center: check for a new version, read its release notes, and see the changelog of earlier versions.
- Run shortcuts: **Ctrl+Enter** runs the query, **Option+X** runs the whole script and **Option+P** runs from the cursor to the end.
- PostgreSQL connections can show only their own database (**Show only the connection's database** in the connection dialog). Databases the user may not connect to are dimmed, and **Connect as Another User…** (on a database's menu, or on a database you may not open) starts a new connection to the same server and database with another user (needs the PostgreSQL driver 0.1.2).
- A connection without a saved password asks for it when it connects and keeps it until TableX quits. Reconnects after sleep or a lost network wait for you instead of asking on their own.
- **Reset Saved Passwords…** (connection overview and command palette) removes every saved password and the AI key; connections and history stay.
- The reconnect banner has smaller buttons.

## Fixes

- macOS no longer asks for the Keychain again and again after **Always Allow**. Saved passwords are now kept encrypted in TableX's own data, behind one Keychain item, and TableX is signed with the same certificate in every release, so what you allow stays allowed after an update.
- A new connection saved without **Save password** now connects: TableX asks for the password.

## Upgrading

Nothing to do. At the first launch, TableX moves your connections, query history, diagrams, open tabs and assistant conversations into one file, `tablex.db`, in its data folder. The old files stay where they are, so TableX 0.1.6 still opens them if you go back.

macOS asks one last time: once for the new Keychain item, and once for each password saved by an earlier version as TableX copies it in. Choose **Always Allow**. If you use the MCP server, update tablex-mcp to 0.1.3 in **Driver Manager → Tools** and run **Allow Keychain access** again.
